# 덕신고 2027 대입 모의면접 평가 시스템 운영 및 배포 안내서

이 안내서는 비개발자 선생님도 클릭 순서대로 따라 하여 시스템을 배포하고 모의면접 행사를 운영할 수 있도록 작성되었습니다.

> **핵심 보안 원칙**
> - 이 시스템은 **학교생활기록부(생기부) 원문·파일·링크를 절대 저장하거나 표시하지 않습니다.**
> - 면접 자료는 학교 노션의 **모의질문 페이지 링크**로만 연결하며, 노션 내용을 앱 안으로 가져오지 않습니다.

---

## 1단계: AI Studio → GitHub 비공개 저장소 연결

1. AI Studio 우측 상단의 **GitHub 아이콘**을 클릭합니다.
2. **Create Private Repository(비공개 저장소 생성)**를 선택합니다.
   - 반드시 **Private(비공개)**로 설정하세요.
3. 저장소 이름을 입력하고 생성·저장(Push)을 완료합니다.
4. 이후 AI Studio에서 코드를 수정한 뒤에도 같은 GitHub 아이콘에서 **Push / Sync** 버튼을 누르면 변경 내용이 GitHub에 반영됩니다.

**확인 방법**
- GitHub 웹페이지에 접속해 방금 만든 저장소에 `wrangler.jsonc`, `migrations/ALL_IN_ONE.sql`, `worker/`, `src/` 폴더가 보이고, 저장소 이름 옆에 **Private** 표시가 있으면 성공입니다.

---

## 2단계: Cloudflare D1 데이터베이스 생성 및 테이블 만들기

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에 로그인합니다.
2. 왼쪽 메뉴에서 **Storage & Databases > D1 SQL Database**를 클릭합니다.
3. 오른쪽 상단 **Create** 버튼을 클릭합니다.
4. Name에 **`mock-interview-db`**를 입력하고 **Create**를 누릅니다.
5. 생성된 `mock-interview-db` 상세 화면에서 **Console** 탭을 클릭합니다.
6. GitHub 저장소의 `migrations/ALL_IN_ONE.sql` 파일 내용을 전체 복사해 Console 입력창에 붙여 넣고 **Execute** 버튼을 누릅니다.

**확인 방법**
- Console 입력창에 아래 SQL을 입력하고 **Execute**를 누릅니다.
  ```sql
  SELECT name FROM universities;
  ```
- 결과 표에 **인하대학교, 인천대학교, 동국대학교** 3곳이 보이면 성공입니다.
- (참고: `ALL_IN_ONE.sql`은 두 번 실행해도 오류가 나지 않도록 설계되어 있습니다.)

---

## 3단계: `wrangler.jsonc`에 `database_id` 입력

1. Cloudflare D1 상세 화면 상단에서 **`Database ID`** (긴 영문+숫자 문자열)를 복사합니다.
2. GitHub 웹페이지에서 내 저장소의 **`wrangler.jsonc`** 파일을 엽니다.
3. 오른쪽 상단의 **연필 아이콘(Edit this file)**을 클릭합니다.
4. `REPLACE_WITH_D1_DATABASE_ID` 부분을 지우고 방금 복사한 실제 `Database ID`를 붙여 넣습니다.
5. 오른쪽 상단 **Commit changes...** 버튼을 눌러 저장합니다.

**확인 방법**
- `wrangler.jsonc` 파일을 다시 열었을 때 `"database_id": "실제ID..."` 형태로 바뀌어 있으면 성공입니다.

---

## 4단계: Cloudflare Workers 연결 및 자동 배포 설정

1. Cloudflare 대시보드 왼쪽 메뉴에서 **Workers & Pages**를 클릭합니다.
2. **Create** 버튼을 누른 뒤 **Continue with GitHub (Import a repository)**를 선택합니다.
3. 1단계에서 만든 비공개 저장소(`mock-interview` 등)를 선택합니다.
4. 빌드 및 배포 설정을 아래와 같이 확인·입력합니다.
   - **Build command**: `npm run build`
   - **Deploy command**: `npx wrangler deploy`
   - **Root directory**: `/` (비워 두거나 `/`)
5. **Save and Deploy**를 클릭해 첫 배포를 진행합니다.

**확인 방법**
- 배포가 완료되면 화면에 `https://mock-interview.본인계정.workers.dev` 형태의 배포 주소가 표시됩니다.

---

## 5단계: Secrets(비밀 환경변수) 등록

비밀번호 암호화, 행사 입장 코드, 최초 운영자 지정을 위해 3개의 Secret을 등록해야 합니다.

1. Cloudflare 대시보드 **Workers & Pages > mock-interview > Settings > Variables and Secrets**로 이동합니다.
2. **+ Add**를 눌러 아래 3개 항목을 각각 **Type: Secret**으로 추가합니다.
   - `ENTRY_CODE`: 교사 자가 등록 시 입력할 행사 입장 코드 (예: `2027-dukshin-interview`처럼 추측하기 어려운 문자)
   - `BOOTSTRAP_ADMIN_EMAIL`: 최초 운영자(선생님)의 이메일 주소
   - `SESSION_SECRET`: 32자 이상의 무작위 영문·숫자 문자열
3. 저장 후 **Deployments** 탭에서 **Retry deployment** 또는 최신 배포를 재배포합니다. (Secret 변경 후 재배포해야 반영됩니다.)

**확인 방법**
- 브라우저에서 `https://배포주소/api/health` 에 접속했을 때 아래처럼 보이면 성공입니다.
  ```json
  {"ok":true,"db":true,"secrets":true}
  ```

---

## 6단계: 최초 운영자 가입 및 로그인 확인

1. 배포 주소(`https://배포주소`)로 접속합니다.
2. **교사 가입 신청** 탭을 클릭합니다.
3. 5단계에서 `BOOTSTRAP_ADMIN_EMAIL`에 등록한 이메일 주소와 `ENTRY_CODE`, 비밀번호(8자 이상)를 입력하고 가입 신청을 누릅니다.
4. `BOOTSTRAP_ADMIN_EMAIL`과 일치하면 승인 대기 없이 **즉시 운영자(admin)로 활성화**됩니다.
5. 로그인한 뒤 개인정보 보호 및 비밀유지 서약에 동의합니다.

**확인 방법**
- 로그인 후 왼쪽 메뉴에 `대시보드`, `진행 보드`, `교사 관리`, `회차 관리` 등 운영자 메뉴가 보이면 성공입니다.

---

## 7단계: 행사 준비 (행사 전날까지)

1. **면접위원 계정 생성**: [교사 관리] → [교사 계정 직접 생성]으로 선생님 계정을 만들고, 화면에 한 번만 표시되는 **12자리 임시 비밀번호**를 복사해 전달합니다. (자가 등록한 선생님은 [승인 대기]에서 역할을 지정해 승인합니다.)
2. **회차 및 면접위원 지정**: [회차 관리] → `1차 모의면접`의 [면접위원 지정]에서 참여 선생님을 모두 선택해 저장합니다.
3. **학생·면접 건 일괄 등록**: [학생·면접 건] → [CSV 일괄 등록]에서 예시 CSV를 내려받아 작성한 뒤 회차를 선택해 등록합니다.
   - 같은 학생이 2개 대학 면접을 볼 경우, 같은 학번으로 2줄을 작성하면 학생 1명에 면접 건 2개가 자동으로 연결됩니다.
4. **노션 모의질문 공유**: 노션에서 각 학생의 모의질문 페이지를 절대 **'웹에 게시'로 공개하지 말고**, 면접위원 선생님의 노션 계정에만 공유하세요.
5. **사전 테스트**: 면접위원 선생님이 본인 휴대폰·태블릿으로 로그인해 첫 비밀번호 변경·서약을 마치고 배정 목록이 보이는지 확인합니다.

**확인 방법**
- [대시보드]에서 등록 학생 수·면접 건수가 일치하고, 면접관 화면에서 [노션 모의질문 열기]가 정상 동작하면 준비 완료입니다.

---

## 8단계: 행사 당일 운영

1. 진행 교사는 노트북/프로젝터에서 **[진행 보드]**를 열어 둡니다.
2. 학생이 입실하면 해당 학생 행의 **[면접 시작]** 버튼을 누릅니다.
   - 5초 안에 모든 배정 면접관의 화면이 자동으로 해당 학생 평가표로 전환됩니다.
3. 면접관은 왼쪽 타이머·노션 모의질문·질문 체크리스트를 보며 오른쪽 평가표에 점수와 조언을 입력하고 **[평가 제출]**을 누릅니다. (2초마다 자동 임시저장)
4. 면접이 끝나면 진행 교사가 **[다음 학생]** 버튼을 눌러 다음 순서로 넘깁니다.
5. 모든 면접이 종료되면 **[결과 취합]**에서 면접관 간 점수 차이가 2점 이상 난 항목(주황색 경고)을 점검하고, **[결과지 관리]**에서 종합 코멘트를 작성해 **확정** 및 **일괄 인쇄(PDF 저장)**를 진행합니다.

**확인 방법**
- 담임교사 화면에서도 실시간으로 제출 완료된 평가가 조회되고, 확정된 학생의 [인쇄] 버튼이 활성화되면 정상입니다.

---

## 9단계: 행사 후 정리 (백업 및 파기)

1. **[결과 취합]** 화면에서 **[CSV 내보내기]**를 눌러 전체 평가 결과를 엑셀 호환 파일로 백업합니다.
2. 확정된 학생별 결과지 PDF를 학생·담임교사에게 전달합니다.
3. [보안·데이터] 화면에 설정한 보관 기한이 지나면, 확인란에 **`파기`**를 입력해 모든 학생·면접 건·평가·결과지 데이터를 영구 파기합니다.

**확인 방법**
- [보안·데이터]의 **감사 로그**에 `EXPORT_CSV`, `PURGE` 기록이 남아 있고 학생 목록이 0건이면 파기 완료입니다.

---

## 10단계: 이후 기능 수정 및 재배포

1. AI Studio에서 수정 사항을 요청해 코드를 반영합니다.
2. GitHub 아이콘을 눌러 비공개 저장소에 동기화(Push)합니다.
3. Cloudflare Workers가 자동으로 새 코드를 빌드해 1~2분 안에 재배포합니다.
4. 만약 데이터베이스 구조(테이블·컬럼)가 바뀐 경우에는 `migrations/0003_...sql` 파일을 Cloudflare D1 Console에서 추가로 실행해 주세요.

## 문제 해결 (FAQ)

- **빌드 실패 로그 확인**: Cloudflare 대시보드 `Workers & Pages > mock-interview > Deployments`에서 실패한 배포를 클릭하면 **Build log**를 볼 수 있습니다.
- **`D1 binding not found` 오류**: `wrangler.jsonc`의 `database_id`가 여전히 `REPLACE_WITH_D1_DATABASE_ID`로 되어 있거나 오타가 있는 경우입니다. 3단계를 다시 확인하세요.
- **`no such table` 오류 (`/api/health`에서 `"db":"no_tables"`)**: D1 데이터베이스만 만들고 `migrations/ALL_IN_ONE.sql`을 실행하지 않은 상태입니다. 2단계를 진행하세요.
- **로그인/가입 실패 (`/api/health`에서 `"secrets":false`)**: 5단계의 `ENTRY_CODE`, `BOOTSTRAP_ADMIN_EMAIL`, `SESSION_SECRET` 3개 중 빠진 항목이 있거나 Secret 저장 후 재배포하지 않은 경우입니다.
- **입장 코드 변경 방법**: Worker Settings > Variables and Secrets에서 `ENTRY_CODE` 값을 수정한 뒤 재배포합니다.
- **교사 비밀번호 분실**: 운영자가 [교사 관리]에서 해당 교사의 **[비밀번호 재발급]**을 누르면 새 12자리 임시 비밀번호가 생성됩니다.
- **행사 당일 네트워크 불안정 대응**:
  1. 면접관 화면 상단에 `"저장 실패 · 다시 시도"`가 뜨면 와이파이/LTE 연결 확인 후 **[임시저장]** 또는 새로고침(`F5`)을 누르세요. 2초마다 서버에 임시저장되므로 이미 저장된 내용은 유지됩니다.
  2. 비상 시에는 진행 보드를 잠시 멈추고 종이 평가표로 기록한 뒤 네트워크 복구 후 입력할 수 있습니다.
